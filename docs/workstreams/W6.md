진행 기록: `docs/workstreams/W6-progress.md`

**시작하기 전에 `docs/workstreams/README.md` 를 읽습니다.**

## 순서

1. **e-graph merge log 의 독립 replay checker.** `src/egraph.c` 가 남기는 merge evidence 를 e-graph 코드와 독립적으로 재생해서 각 merge 가 기록된 rule 로 정당화되는지 검사합니다. W1 의 `ir_verify.c` 가 builder 검증과 코드를 공유하지 않는 것과 같은 원칙입니다.
2. **rewrite rule 별 soundness 조건과 side condition 을 versioned evidence 에 기록.** 지금 rule_name 문자열만 남습니다. 규칙의 전제(비트 폭, 부호 해석, 오버플로 조건)가 evidence 에 실려야 checker 가 검사할 것이 생깁니다.
3. **여러 method 의 병렬 실행을 증거 우선 규칙으로 결합.** 다수결 금지. `PROVED_*` 는 checker 통과 또는 명시된 신뢰 정책이 있는 쪽만, `COUNTEREXAMPLE` 은 replay 된 쪽만 이기고, 충돌(한쪽 proof, 한쪽 replay 된 반례)은 즉시 상태 오류로 표면화합니다. 그 충돌은 버그의 증거이므로 삼키면 안 됩니다.
4. **persistent artifact/evidence cache.** BLAKE3 identity 로 디스크에 저장하고 재사용합니다. 위치는 호출자가 정합니다.
5. **cache key 완전성 통합 검증.** method/backend version, option, semantic contract 중 하나라도 key 에서 빠지면 다른 질문의 답을 재사용하게 됩니다. 각 축을 바꿔서 key 가 바뀌는지 시험으로 고정합니다.
