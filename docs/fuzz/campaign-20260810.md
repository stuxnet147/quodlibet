# Fuzz campaign 2026-08-10

A bounded libFuzzer campaign over every `tests/fuzz/fuzz_*.c` target, run to
settle the G8 exit condition ("fuzz the parser, the lowering, the IR decoder
and the precondition parser, and reach zero crashes").

**Result: not crash-free.** Seven of nine targets ran their full 60 seconds
clean. Two crashed on the empty input, both from one defect in `src/policy.c`.

## How it was run

Host: WSL2 Ubuntu-24.04 on Windows 11, clang 18.1.8, glibc 2.39, ninja.
`-fsanitize=fuzzer` is Clang/Linux only, so this cannot be run from the Windows
side of the checkout.

```sh
cmake --preset linux-fuzz          # QL_BUILD_FUZZERS=ON, ASan+UBSan+fuzzer
cmake --build --preset linux-fuzz --parallel
scripts/coordinator/fuzz-campaign.sh
```

The campaign was run from a copy of the worktree on a WSL-native path rather
than through `/mnt/c`, because the `/mnt/c` translation layer dominates both
build time and the fuzzer's own file I/O. Nothing in the build depends on the
location; `fuzz-campaign.sh` resolves `out/build/linux-fuzz` relative to
itself, so the copy and the campaign stay consistent.

Each target gets `-max_total_time=60` under a `timeout 70` guard. Wall clock for
the whole campaign was about 7 minutes: seven targets at 60 seconds plus two
that died in their first execution.

## The two crashes

Both are the same defect, at two call sites, and neither needs a crafted input:
the empty input is enough.

```text
fuzz_policy         -> ql_policy_parse        src/policy.c:650
fuzz_policy_result  -> ql_policy_result_parse src/policy.c:1196
AddressSanitizer: heap-buffer-overflow, READ of size 2, inside strlen
```

Both functions carry an undocumented sentinel:

```c
if (json_size == 0u) {
    json_size = strlen(json);
}
```

A caller that honours the pointer-plus-length signature and passes a
zero-length slice of a buffer that is not NUL-terminated gets a read past the
end of the allocation. `include/quodlibet/policy.h` documents no such
convenience, and no other decoder in the tree uses it: `ql_precondition_parse`,
`ql_problem_open` and `ql_source_signature_open` all take the length as given,
which is why the other seven targets survive the same empty input. The pattern
appears at exactly these two places in `src/`.

Reproduce, from a `linux-fuzz` build:

```sh
out/build/linux-fuzz/fuzz_policy        tests/fuzz/corpus/policy
out/build/linux-fuzz/fuzz_policy_result tests/fuzz/corpus/policy_result
```

Both corpora now carry an `empty-input` seed for exactly this, so the crash is
replayed by a named file rather than by whatever the mutator happens to try
first.

`src/policy.c` is owned by another workstream, so the fix is not made here. It
is one line at each site, and the choice is between rejecting a zero length as
an empty document and documenting the sentinel in the public header. The
header's contract is pointer plus length everywhere else, which argues for the
former.

## Note on the campaign script

`scripts/coordinator/fuzz-campaign.sh` reads `$?` after a pipeline that ends in
`tail`, so the `exit=` it prints is `tail`'s status and is `0` even for these
two crashes. Read the `ERROR:`/`SUMMARY:` lines, not the printed exit code,
until that is corrected. The script is not owned here either.

## G8

Not closed. Seven targets are crash-free over a bounded minute each, including
every surface G8 names, but `ql_policy_parse` and `ql_policy_result_parse`
still crash on an empty input. G8 closes when those two are fixed and this
campaign is rerun end to end.
