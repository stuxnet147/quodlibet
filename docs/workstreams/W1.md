# W1. semantic C frontend 와 IR semantics

브랜치: `w1-semantic-c-frontend`
담는 GOAL: G5 전반부, G8 전부, G9 전부
진행 기록: `docs/workstreams/W1-progress.md`

**시작하기 전에 `docs/workstreams/README.md` 를 읽습니다.**

## 이 워크스트림이 지는 것

Quodlibet 의 어려운 문제는 orchestration 이 아니라 **C semantics 에서 proof semantics 로 넘어가는 경계의 정확성**입니다. 그 경계가 여기입니다. 개발력의 가장 큰 몫이 이 워크스트림입니다.

지금 `src/c_lower.c` 가 받는 것은 **루프 없는 정수와 `_Bool`** 뿐입니다. 포인터, 호출, 루프, 구조체, `volatile`, `_Atomic` 은 전부 `QL_C_LOWER_UNKNOWN` 으로 떨어집니다. G9 는 실제 코퍼스의 99% 를 받으라고 요구합니다. 그 사이를 메우는 것이 이 일이고, **수용률을 정확성과 바꾸지 않는 것**이 조건입니다.

## 소유하는 파일

이 파일들만 고칩니다.

- `src/c_frontend.c`, `include/quodlibet/c_frontend.h`
- `src/c_lower.c`, `include/quodlibet/c_lower.h`
- `src/ir.c`, `include/quodlibet/ir.h`
- 새로 만들 것: `src/c_lower_expr.c`, `src/c_lower_stmt.c`, `src/c_types.c`, `src/ir_verify.c`, `src/ir_interp.c` 와 그 헤더
- `tests/test_c_frontend.cpp`, `tests/test_c_lower.cpp`, `tests/test_ir.cpp` 와 새 `tests/test_ir_interp.cpp`, `tests/test_c_lower_*.cpp`
- `docs/workstreams/W1-progress.md`, `docs/lowering/` (새로 만듦)

`src/c_syntax.c` 는 안정된 tree-sitter 경계입니다. 꼭 필요한 것이 아니면 손대지 않습니다.

**`include/quodlibet/ir.h` 는 W2 가 지금 읽고 있습니다.** 기존 타입과 열거값의 뜻을 바꾸지 말고 **append-only** 로만 넓힙니다. 넓힐 때마다 진행 기록에 한 줄 적습니다.

## 순서

정확성 장치를 먼저 만들고 그 다음에 수용 범위를 넓힙니다. 반대로 하면 무엇이 깨졌는지 알 수 없습니다.

### 1단계. 정확성 장치 (G8)

이것이 없으면 뒤의 확장이 전부 근거 없는 확장입니다.

- **IR verifier** (`src/ir_verify.c`). 타입 일치, SSA 정의-사용 지배관계, 블록 종결, PHI 인자와 선행 블록 대응, effect 비트와 실제 연산의 일치, UB guard 가 붙어야 하는 연산에 붙어 있는지를 검사합니다. **로어링 출력은 항상 이것을 통과해야 하고**, 통과 검사를 로어링 시험 전부에 걸어 둡니다.
- **IR concrete interpreter** (`src/ir_interp.c`). 타입이 있는 입력을 받아 IR 을 실제로 실행하고 관찰 가능한 결과(반환값, trap, 종료, 메모리, 이벤트 트레이스)를 냅니다. UB 에 닿으면 `UB` 를 결과로 냅니다. **이것은 W2 의 counterexample replay 가 그대로 쓸 부품입니다.** 인터페이스를 진행 기록에 적어 W2 가 볼 수 있게 합니다.
- **differential 시험**. 같은 C 함수를 (가) 로어링해서 인터프리터로 돌린 것과 (나) clang 으로 컴파일해서 실제로 돌린 것이 무작위 입력에서 일치하는지 봅니다. 불일치는 전부 버그입니다. 시험 하네스를 `tests/` 에 두고 clang 이 없는 환경에서는 skip 이 아니라 **미실행을 명시**합니다.
- **퍼저**. 파서, 로어링, IR 디코더에 걸고 크래시 0 을 확인합니다. libFuzzer 또는 그에 준하는 것. Linux sanitize 프리셋에서 돌립니다.

### 2단계. 커버리지 측정에 따른 확장 (G9)

W4 가 커버리지 도구를 만들면 그 진단 분포가 우선순위를 줍니다. **W4 를 기다리지 말고**, 그 전에는 `datasets/records-local` 의 표본을 직접 걸어서 자기 분포를 냅니다. 경로는 `D:/projects/machine-model/datasets/records-local` 이고 레코드 198,432 개입니다.

빈도가 높을 것으로 예상되는 순서이지만 **측정이 이 순서를 이깁니다.**

1. 정수 promotion 과 usual arithmetic conversion 을 C11 6.3.1.8 대로. 지금 구현이 이것을 정확히 하는지 먼저 확인합니다
2. 포인터: 연산, object identity, provenance, 유효 범위, alignment
3. 배열과 구조체, 공용체, 비트필드, enum
4. 함수 호출과 외부 효과, 호출 순서 관찰
5. `switch`, `goto`, 레이블, 중첩 제어 흐름
6. 루프: 구조를 보존한 하강. bounded unrolling 은 W2 와 경계를 나눕니다
7. 전역 변수와 정적 저장 기간
8. `volatile`, `_Atomic`, I/O

### 3단계. 확장성 (G8)

- `docs/lowering/adding-a-construct.md` 에 **새 C 구문 하나를 추가하는 절차**를 씁니다. 어디를 고치고 어떤 시험을 추가하고 무엇을 검증하는지입니다.
- 그 절차대로 실제로 구문 하나를 추가한 커밋을 남깁니다. 문서가 맞는지는 그렇게만 확인됩니다.

## 종료 조건

`GOAL.md` 의 G8 과 G9 전문이 이 워크스트림의 종료 조건입니다. 요약하면 이렇습니다.

- 파서 수용률 >= 99%, IR 로어링 수용률 >= 99% (`UNKNOWN` 은 미달)
- 미달분이 진단 코드별로 분류되어 남는다
- IR verifier 가 로어링 출력 전부에 대해 통과한다
- differential 시험이 무작위 입력에서 실제 실행과 일치한다
- 퍼징 크래시 0
- 로어링 처리량(함수/초)이 측정되어 기록된다
- 새 구문 추가 절차가 문서에 있고 그대로 추가한 예가 있다

## 하지 않는 것

- SMT 인코딩, product program, solver 호출은 W2 입니다
- 로깅, 예산, 판정 정책은 W3 입니다
- 파이썬 바인딩과 커버리지 측정 도구는 W4 입니다
- scheduler 와 plugin 기능 확장은 이 기간에 하지 않습니다
