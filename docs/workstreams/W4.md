## 이 워크스트림이 지는 것

Quodlibet 은 asm2c 강화학습기의 채점기로 불릴 예정입니다. 파이썬에서 부르는데 ctypes/cffi 처럼 ABI 를 런타임에 재선언하는 FFI 가 아니라 **CPython C 확장 모듈**로 만듭니다. 그 방식이 요구사항입니다.

지금 코어에는 판정 경로가 실제로 있습니다. `prove.smt-product` 가 loop-free scalar C 두 함수에 대해 `PROVED_*`, `COUNTEREXAMPLE`, `UNKNOWN` 을 냅니다. W3 의 예산(`budget.h`)과 판정 정책(`policy.h`)도 공개 API 에 있습니다. 이것들을 파이썬으로 노출하는 것이 이 일입니다.

## 소유하는 파일

## 설계 제약

- **CPython C API 직접 사용.** pybind11 은 C++ 이므로 쓰지 않습니다. 코어가 C17 이고 공개 헤더가 C 이므로 순수 C 확장이 자연스럽고 의존성이 늘지 않습니다.
- **`Py_LIMITED_API` (abi3).** 파이썬 마이너 버전마다 다시 빌드하지 않습니다. 3.11 을 하한으로 잡습니다(`Py_LIMITED_API=0x030B0000`).
- **GIL 을 solver 대기 동안 놓습니다.** `Py_BEGIN_ALLOW_THREADS` 로 method 실행을 감쌉니다. RL 루프의 다른 스레드가 굶으면 안 됩니다.
- **소유권 규율.** C 쪽 artifact 와 registry 의 수명을 파이썬 객체 수명에 정확히 묶습니다. 해제 순서(플러그인 -> registry)를 지킵니다.
- 오류는 `ql_status` 와 `ql_error.message` 를 파이썬 예외로 옮깁니다. 조용히 삼키지 않습니다.

## 노출할 API (최소)

```python
import quodlibet

# 판정 한 건
result = quodlibet.check(
    left_source="int f(int a){return a+a;}",
    left_function="f",
    right_source="int g(int a){return 2*a;}",
    right_function="g",
    relation="equivalence",          # left-refines-right, right-refines-left
    ub_policy="both-defined",        # must-match, language-refinement
    trust_smt_backend=True,          # 명시적 trusted-backend 선택
    budget={"total_ms": 5000, "solver_ms": 3000, "memory_bytes": 1 << 30},
    policy_json=None,                # G3 판정 정책 JSON
)
result.verdict      # "proved-equivalent" | "counterexample" | "unknown" | ...
result.status       # 상태와 오류 메시지
result.evidence     # 증거 envelope 요약 (checked_proof=False 포함)
result.counterexample  # replay 된 입력, 없으면 None

# 강화학습기용 배치. 스레드 풀에서 병렬로 돌고 GIL 을 놓는다
results = quodlibet.check_batch([spec1, spec2, ...], workers=0)
```

이름과 형태는 다듬어도 되지만 **배치 경로와 예산과 정책 노출은 줄이지 않습니다.**

## 빌드

- `bindings/python/pyproject.toml` 로 `pip install .` 이 되게 합니다. scikit-build-core 로 CMake 를 부르는 것이 코어와 자연스럽게 맞습니다.
- 코어 라이브러리는 정적으로 링크해서 확장 모듈 하나가 자기완결이 되게 합니다. Bitwuzla 실행 파일은 모듈 옆이 아니라 `QL_BITWUZLA_EXECUTABLE` 로 찾으므로, 파이썬 쪽에서 실행 파일 경로를 지정하는 인자를 노출합니다.
- Windows 와 Linux 양쪽에서 빌드되고 import 됩니다. 여기(Windows)서 만들고 Linux 는 조율자가 VM 확인(G7) 때 돌립니다.

## 시험

- `bindings/python/tests/` 에 pytest. 왕복(판정 세 종류가 실제로 나오는지), 예산 초과가 `UNKNOWN` 으로 오는지, 정책 거부가 예외로 오는지, GIL 해제(동시 check 가 실제로 겹치는지), 소유권(GC 후 크래시 없음).
- CTest 에 파이썬 시험을 하나 걸어서 `ctest` 만 돌려도 바인딩이 깨졌는지 알 수 있게 합니다. 파이썬이 없는 환경에서는 skip 이 아니라 미실행 명시입니다.
