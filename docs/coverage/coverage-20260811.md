## 이번 단위가 더한 몫

| | 이전 | 이후 |
|---|---:|---:|
| train 로어링 | 5,187 | **6,129** |
| val 로어링 (1,050 중) | 209 | **251** |
| val 판정률 | 188/209 (90.0%) | **244/251 (97.2%)** |

두 가지를 닫았습니다.

- **`scalar_t__` 를 signature 표에서도 코퍼스 사실로** (val 판정 16건). 표를 복제하지 않고 로어링이 읽는 같은 표를 읽습니다. 사실을 두 벌 두면 어긋나고, signature 의 타입 모델을 따로 쓰는 가치는 모델링을 두 번 검사하는 것이지 코퍼스 사실을 두 번 적는 것이 아닙니다
- **포인터로의 cast** (train +942, val +42). 이 프로파일에서 포인터는 곧 주소이므로 cast 는 재해석이고 값을 바꾸지 않습니다. 주소가 온 object 도 같이 따라가므로 cast 뒤의 역참조가 cast 전보다 덜 알려지지 않습니다. 배열이나 함수 타입으로의 cast, 세 단계 이상의 indirection 은 계속 거부합니다

## 정확성을 대가로 지불하지 않았습니다

같은 표본에서 두 장치를 같이 돌렸습니다.

| | 이전 | 이후 |
|---|---:|---:|
| **verifier**: train 로어링 중 통과 | 5,187 / 5,187 | **6,129 / 6,129** |
| verifier 실패 | 0 | **0** |
| **differential**: 직렬 `ctest` | 497 / 497 | **499 / 499** |
| status 실패 (한계는 언제나 UNKNOWN) | 0 | **0** |

differential 은 컴파일된 참조 함수와 인터프리터 실행을 비교하고, verifier 는 그 시험들이 만드는 모든 로어링에 대해 돕니다. cast 에 대해서는 `void *` 를 거쳐 되돌아오는 경우와 `char *` 로 재해석해 바이트 단위로 읽는 경우를 새로 더했습니다. 뒤엣것은 cast 타입이 첨자의 보폭을 정한다는 것을 컴파일된 실행만이 말해 줄 수 있어서 넣었습니다.

verifier 계측은 커버리지 도구가 조율자 소유이므로 넣었다가 재고 되돌렸습니다. 도구 자체는 바뀌지 않았습니다.

## 재현

```sh
./out/build/windows-clang/quodlibet.exe coverage \
    out/corpus/train/units.txt out/corpus/train/detail.tsv
cut -f4 out/corpus/train/detail.tsv | sort | uniq -c | sort -rn
```

판정률은 `tools/corpus/verdict_rate.py` 로 val 에서 잽니다. CMake 가 고른 Python 으로 돌려야 합니다. 다른 인터프리터에서는 확장 모듈이 `PY_SSIZE_T_CLEAN` 으로 거절합니다.
