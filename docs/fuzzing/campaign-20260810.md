# libFuzzer 캠페인 2026-08-10

G8 의 "퍼저를 걸고 크래시 0 확인" 에 대한 첫 유도(coverage-guided) 캠페인 기록입니다.

## 방법

- `linux-fuzz` 프리셋 (WSL Ubuntu 24.04, Clang, ASan+UBSan, 라이브러리 전체에 `-fsanitize=fuzzer-no-link`)
- 타깃 셋: `fuzz_c_frontend`, `fuzz_c_lower`, `fuzz_ir_decoder` (`tests/fuzz/`, W1 소유. 크래시만 보지 않고 SUPPORTED 로어링은 verifier 를 통과해야 한다는 불변식까지 검사)
- 타깃당 60초, `scripts/coordinator/fuzz-campaign.sh`
- main `199654e` + linux-fuzz 프리셋 수정

## 처음 캠페인은 눈먼 것이었다

첫 실행은 cov 5/3/2 를 냈다. 라이브러리가 `-fsanitize=fuzzer-no-link` 없이 빌드되어 libFuzzer 가 드라이버 파일 자체의 엣지만 보고 라이브러리 안은 전혀 보지 못했다. **cov 가 한 자리이면 그 캠페인은 무작위이지 유도가 아니다.** 실행 수가 260만이어도 근거가 못 된다. `linux-fuzz` 프리셋이 이제 라이브러리 전체에 계측을 넣는다.

## 재현

```sh
cmake --preset linux-fuzz
cmake --build --preset linux-fuzz --parallel
bash scripts/coordinator/fuzz-campaign.sh
```

더 긴 캠페인(시간 단위)은 VM 확인(G7) 때나 필요할 때 같은 스크립트로 시간만 늘려 돌린다. precondition 파서 퍼저는 아직 없고 G8 종료 조건에 들어 있으므로 W1 또는 조율자가 추가해야 한다.
