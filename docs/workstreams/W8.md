# W8. 성능 튜닝 (G6 인수)

브랜치: `w8-performance`
담는 것: GOAL G6 전부. 조율자가 하던 것을 인수합니다
진행 기록: `docs/workstreams/W8-progress.md`

**시작하기 전에 `docs/workstreams/README.md` 와 `docs/perf/baseline.md` 를 읽습니다.** baseline 문서가 이 워크스트림의 출발점이자 방법론입니다.

## 물려받는 상태

- Windows VTune 은 이 호스트에서 죽어 있습니다(다섯 프로브 실측). **프로파일링은 WSL Ubuntu-24.04 의 VTune** (`/opt/intel/oneapi/vtune/latest/bin64/vtune`) 으로 합니다. `kernel.yama.ptrace_scope=0` 필요.
- hotspots 기준선: val 1,050 유닛 0.380s CPU, tree-sitter 파싱 지배.
- 적용된 최적화 1건: coverage 경로 중복 파스 제거 (-27%).
- **알려진 다음 한 방**: 프런트엔드와 로어링이 유닛당 각각 파싱합니다. 트리를 한 번 만들어 넘기는 append-only API(`_with_tree` 변형)가 파싱 비용 절반을 지웁니다. 그 파일들은 W1 소유이므로 **W1 과 ask/조율자 경유로 인터페이스를 합의**한 뒤 W1 이 API 를 내고 당신이 소비자(coverage, 나중엔 bindings)를 옮기는 분업이 자연스럽습니다.
- WSL 에서 VTune threading 수집은 걸립니다(실측). threading 리포트는 W9 의 VM 에서 나올 것이니 거기 결과를 받아 씁니다.

## 규율

- **프로파일 없이 가설 없음. 소거법 금지.** 모든 최적화 커밋에 before/after 수치.
- **프로파일링은 항상 볼 것만 좁혀서 백그라운드 + 120초 제한.** 백그라운드 timeout 은 강제되지 않으므로 넘긴 것은 직접 끊습니다.
- 튜닝이 건전성을 바꾸지 않았음을 매번 전체 CTest 로 확인합니다.
- 수치와 방법은 전부 `docs/perf/` 에 잇습니다.

## 소유하는 파일

- `docs/perf/` 전부, `scripts/coordinator/vtune-wsl.sh`
- 최적화 대상 파일은 소유자가 따로 있으면 ask 로 합의 후 진행합니다. 소유자 없는 파일(예: `cli/`)은 직접.
