# W2. 첫 exact backend

브랜치: `w2-exact-backend`
담는 GOAL: G5 후반부
진행 기록: `docs/workstreams/W2-progress.md`

**시작하기 전에 `docs/workstreams/README.md` 를 읽습니다.**

## 이 워크스트림이 지는 것

지금 Quodlibet 은 판정을 한 건도 내지 못합니다. `quodlibet methods` 가 `builtin.identity` 하나만 보여줍니다. IR, e-graph, Bitwuzla 어댑터가 라이브러리로는 있는데 **파이프라인 method 로 물려 있지 않고 좌우 두 함수를 결합하는 것이 없습니다.**

이 워크스트림이 그 수직 절단을 끝냅니다. 끝나면 loop-free scalar C 두 함수에 대해 `PROVED_*`, `COUNTEREXAMPLE`, `UNKNOWN` 이 실제로 나옵니다.

**절대로 넘지 않는 선이 있습니다.** raw solver `UNSAT` 은 그 자체로 proof 가 아니고, replay 하지 않은 SAT model 은 확정 counterexample 이 아니고, `BOUNDED_CLEAN` 은 proof 가 아닙니다. 이 셋을 지키는 것이 이 워크스트림의 값어치 전부입니다. 빨리 판정을 내려고 이 선을 넘으면 만든 것이 쓸모없어집니다.

- `tests/test_problem.cpp`, `tests/test_solver.cpp`, `tests/test_proof_method.cpp`, `tests/test_proof_registry.cpp`, `tests/test_evidence.cpp` 와 새 시험들
- `docs/workstreams/W2-progress.md`

`src/builtins.c` 에 proof method 를 등록해야 하면 조율자에게 말합니다.

**`include/quodlibet/ir.h` 는 W1 이 소유합니다.** 읽기만 합니다. IR 에 필요한 것이 있으면 진행 기록에 적고 조율자를 거쳐 W1 에 요청합니다. 지금 있는 loop-free scalar IR 만으로 첫 절단이 됩니다.

## 순서

### 1단계. 문제를 정확히 진술하는 것

증명하기 전에 **무엇을 증명하는지**가 결합되어 있어야 합니다. 지금 problem v1 은 그렇지 않습니다.

- **versioned source-signature artifact** (`src/signature.c`). 인자와 반환의 signedness, width, pointer/address-space, ABI 정보를 보존합니다. IR 의 비트벡터 타입은 signedness 를 담지 않으므로 이것이 별도 artifact 여야 합니다(`ARCHITECTURE.md` 의 IR schema v1 절).
- **problem schema v2**. 좌우 signature digest, 좌우 인자 대응, typed-precondition digest 를 한 artifact 에 결합합니다.
- **v1 gate**. problem v1 의 non-null precondition 으로는 `PROVED_*` 를 낼 수 없게 코드가 막습니다. 시험으로 고정합니다.

### 2단계. 관계를 SMT 로 옮기는 것

- **product program 또는 SMT miter** (`src/product.c`). 좌우 loop-free scalar IR 을 결합합니다.
- relation 방향(`EQUIVALENCE`, `LEFT_REFINES_RIGHT`, `RIGHT_REFINES_LEFT`), UB policy 세 가지, 관찰 축(반환값, termination, trap)이 query 에 **정확히** 반영되어야 합니다. `ARCHITECTURE.md` 의 "Logical result contract" 절이 그 뜻을 정의합니다. 뜻을 좁게 해석해서 통과시키지 않습니다.
- 관찰 축 하나를 잘못 빠뜨리면 틀린 `PROVED_*` 가 납니다. **각 축을 개별로 고정하는 시험**을 씁니다. 축을 끄면 통과하고 켜면 반례가 나오는 쌍을 시험으로 둡니다.

### 3단계. 결과를 믿을 수 있게 만드는 것

- **SAT model decode** (`src/replay.c`). Bitwuzla 의 model 을 typed input 과 관찰 가능한 witness 로 되돌립니다.
- **concrete replay**. decode 한 입력을 좌우 양쪽에서 실제로 실행해서 관계가 정말 깨지는지 확인합니다. **확인된 뒤에만 `COUNTEREXAMPLE` 을 냅니다.** 확인이 안 되면 `UNKNOWN` 입니다. 이 경우는 인코딩 버그이므로 로그로 남깁니다.
  - 실행기는 W1 이 만드는 `src/ir_interp.c` 입니다. W1 의 진행 기록에서 인터페이스를 봅니다. **아직 없으면 필요한 인터페이스를 정의해서 진행 기록에 적고, 임시로 자기 쪽 최소 실행기를 만들어 진행합니다.** W1 것이 나오면 갈아탑니다.
- **UNSAT 승격 경계**. 둘 중 하나를 고르고 문서에 적고 코드가 강제하게 합니다.
  - (가) 신뢰 가능한 checker 가 UNSAT 증거를 검증한다
  - (나) 명시적 trusted-backend policy 로 Bitwuzla 를 신뢰하되, 그 신뢰가 결과 envelope 에 기록되고 사용자가 그것을 볼 수 있다
  - 어느 쪽이든 **problem, contract, query, backend identity 가 결합된 뒤에만** `PROVED_*` 가 나옵니다. Bitwuzla 스냅샷의 BLAKE3 가 이미 있습니다(`SOLVERS.md`).
- **method 등록**. 만든 proof method 가 registry 에 등록되어 `quodlibet methods` 에 나오고 파이프라인 JSON 에서 이름으로 선택됩니다.

### 4단계. end-to-end

- `PROVED_*` 가 나오는 쌍, `COUNTEREXAMPLE` 이 나오는 쌍, `UNKNOWN` 이 나오는 쌍 각각에 대한 통합 시험
- CLI 에서 C 파일 둘을 주고 판정을 받는 경로. 조율자가 CLI 를 소유하므로 필요한 것을 진행 기록에 적고 말합니다

## 종료 조건

`GOAL.md` 의 G5 전문입니다. 요약하면 이렇습니다.

- problem schema v2 가 좌우 signature digest, 인자 대응, precondition digest 를 결합한다
- product program 또는 miter 가 있다
- relation 방향, UB policy, 관찰 축이 query 에 정확히 반영되고 각각을 고정하는 시험이 있다
- SAT model 이 typed input 으로 decode 되고 concrete replay 로 확인된 뒤에만 `COUNTEREXAMPLE` 이 난다
- UNSAT 승격 경계가 문서에 적히고 코드가 강제한다
- 세 결과의 end-to-end 통합 시험이 있다

## 하지 않는 것

- C 로어링 확장은 W1 입니다. 지금 있는 loop-free scalar 슬라이스로 첫 절단을 끝냅니다
- 로깅, 예산, 판정 정책은 W3 입니다. solver 타임아웃 축이 W3 의 예산과 만나면 조율자를 거칩니다
- AIG/SAT backend, CHC/PDR, bounded execution 은 지금 하지 않습니다
- scheduler 와 plugin 기능 확장은 이 기간에 하지 않습니다
