**시작하기 전에 `docs/workstreams/README.md` 를 읽습니다.**

## 순서 (측정이 순서를 이깁니다)

1. **퍼저 확대.** `tests/fuzz/` 에 precondition 파서와 artifact/IR 디코더 경계의 남은 표면(problem v1/v2, signature, policy JSON)을 추가합니다. 기존 fuzz_targets.h 방식을 따르고 `scripts/coordinator/fuzz-campaign.sh` 로 돌려 크래시 0 을 기록합니다.
2. **solver fault-injection 확대.** crash, timeout, corrupt model, 잘린 출력, 폭주 출력. 기존 시험이 다루는 것을 먼저 조사하고 빠진 축만 더합니다.
3. **동시성 측정.** 병렬 worker 수와 solver 동시성별 처리량, cancellation overhead. `bindings` 의 `check_batch` 를 부하 생성기로 쓰면 됩니다. 수치는 `docs/perf/` 에.
4. **ABI 호환 시험과 plugin SDK 예제.** `struct_size`/`abi_version` 규약이 실제로 지켜지는지(작은 구버전 구조체를 넘겨 거부되는지), 최소 플러그인 예제 하나.
5. **설치 패키지.** Windows 와 Linux 에서 `cmake --install` 결과가 자기완결인지, relocatable Bitwuzla 탐색(실행 파일 옆)이 실제로 작동하는지.
6. **지원 compiler/target matrix 자동 검증.** `D:/projects/machine-model/datasets/records-local/summary.json` 의 compilers/optimizations 를 읽어 `ASM2C_GNU_V1` 프로파일의 provenance 표와 대조하는 시험.

## 소유하는 파일

- `docs/perf/` 의 동시성 측정 절 (W8 과 겹치면 ask)
