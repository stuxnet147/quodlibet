## 이번 단위가 더한 몫

| | 이전 | 이후 |
|---|---:|---:|
| train 로어링 | 6,129 | **7,233** |
| val 로어링 (1,050 중) | 251 | **288** |
| val 판정률 | 244/251 (97.2%) | **279/288 (96.9%)** |

세 가지를 닫았습니다.

- **AnghaBench preamble 의 나머지 typedef** (train +294). `size_t`, `intptr_t`, `uintptr_t` 입니다. 지난 단위가 `scalar_t__` 하나만 옮겨 적었는데, preamble 은 고정 블록이고 record 추출이 그 블록 전체를 버립니다. 2,000 파일 표본에서 `size_t` 를 언급하는 1,981 파일 전부가 `typedef unsigned long size_t;` 를 선언하고 다른 철자는 없으며, `intptr_t` 와 `uintptr_t` 는 같은 1,981 파일의 같은 한 줄에서 옵니다. 추측이 아니라 전사입니다. 첫 차단 사유였던 미해석 철자 3,998 건 중 3,345 건이 이 세 이름이었습니다
- **포인터를 반환하는 콜리 선언** (train +810). `T *f(...)` 는 function declarator 가 pointer declarator 안에 들어 있는데 수집기가 declaration 바로 아래의 function declarator 만 보고 있어서, 그런 콜리는 **선언이 있는데도 선언이 없다고** 보고되고 있었습니다. `unsupported_call` 4,820 중 4,815 가 이것이었고 지금은 29 입니다. 별은 반환 타입의 것이므로 그 자리에서 세어 반환 타입에 싣습니다
- **`f(void)` 프로토타입**. 콜리 파라미터 위치의 `void` 가 객체 타입이 아니라는 이유로 `type_error` 를 내고 있었습니다. C 에서 `f(void)` 는 파라미터가 하나도 없다는 뜻이므로 타입을 풀기 전에 알아봐야 합니다. 첫 차단 수는 바뀌지 않았지만(0건) 평범한 C 프로토타입에 오류를 내던 것을 고쳤습니다

## 정확성을 대가로 지불하지 않았습니다

같은 표본에서 두 장치를 같이 돌렸습니다.

| | 이전 | 이후 |
|---|---:|---:|
| **verifier**: 로어링 시험이 만드는 모든 IR | 통과 | **통과** |
| **differential**: 직렬 `ctest` | 503 / 503 | **507 / 507** |
| status 실패 (한계는 언제나 UNKNOWN) | 0 | **0** |

새 differential 은 두 가지입니다.

- `CLowerCalls.MatchesCompiledExecutionForACalleeThatReturnsAPointer`: 콜리가 **하위 32비트가 0 인 주소**를 돌려주고 본문이 그것을 null 과 비교합니다. 반환 폭이 32비트였다면 주소가 null 로 잘려 반대 답이 나옵니다. 별을 반환 타입에 실었다는 것을 컴파일된 실행만이 말해 줄 수 있는 형태로 골랐습니다
- `CLowerTypes.ResolvesTheRestOfTheCorpusPreamble`: `size_t` 를 32비트 왼쪽 shift 하고, `intptr_t` 를 부호 반전하고, `uintptr_t` 를 32비트 오른쪽 shift 합니다. 폭과 부호가 셋 다 답에 드러납니다

`CLowerTypes.LetsTheUnitOverrideAPreambleTypedef` 가 표가 덮어쓰기가 아니라 fallback 이라는 것을 고정합니다. unit 이 `typedef unsigned short size_t;` 를 선언하면 그쪽이 이깁니다.

`CLowerCalls.WillNotDereferenceAPointerACalleeReturned` 가 건전성 쪽을 고정합니다. 콜리가 돌려준 포인터에는 guard 가 이름 붙일 object 가 없으므로 역참조는 계속 거부합니다. 콜리 선언을 찾게 되었다고 해서 provenance 규칙이 느슨해지지 않았습니다.

## 재현

```sh
./out/build/windows-clang/quodlibet.exe coverage \
    out/corpus/train/units.txt out/corpus/train/detail.tsv
cut -f4 out/corpus/train/detail.tsv | sort | uniq -c | sort -rn
```

판정률은 `tools/corpus/verdict_rate.py` 로 val 에서 잽니다. CMake 가 고른 Python 으로 돌려야 합니다. 다른 인터프리터에서는 확장 모듈이 `PY_SSIZE_T_CLEAN` 으로 거절합니다.

버킷 안의 분포를 보려면 `cli/coverage.c` 의 detail 행에 진단 메시지 열을 임시로 붙여 재고 되돌립니다. 그 도구는 조율자 소유이므로 계측을 커밋하지 않았습니다.
